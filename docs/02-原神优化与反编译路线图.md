# 原神深入优化与反编译信息获取路线图

> 生成日期：2026-08-21 ｜ 团队：technical-artist / unity-shader-graph-artist / unity-architect / specialized-codebase-archaeologist / engineering-developer-tooling-engineer

## 0. 现状一句话

Bridge 的 TAAU 替换主识别手段已是**结构化内省**（SRV/RTV 布局 + weights 16×16 + cb0≥464 + jitter@448），版本韧性最好；真正的脆弱点是**字节签名**（RenderScaleMenu/AntiPlayerMosaic 的函数定位）、**硬编码对象偏移（+0x88）**、**对游戏内部语义的猜测**（motion 解码曲线、FOV、reactive mask）。

## 1. 渲染质量风险与修复（technical-artist + shader-graph-artist）

### 1.1 Mask 语义（高优先核实项）
- **文档误导**：`Dx11FsrBridge.package.ini:69-75` 两条注释都写「将 T4 传入」，但代码实际是 reactive=`motion.z`（`Fsr2TranslationLayer.cpp:200`）、transparency=`flags 二值化`（`:201`）——注释应先修正。
- **reactive=motion.z 是脆弱启发式（未确认）**：2D motion 纹理的 `.z` 大概率不是引擎 reactive 信号（恒 0 → FSR2 激进复用历史 → 鬼影；噪声 → 频繁 reset → 闪烁）。建议：改由 depth+motion 残差或 |motion| 推导，或加专用 mask pass（深度历史拒绝 + 运动 + 透明度融合）。
- **transparency 硬二值化**：`flags>0?1:0` 丢失渐变透明度，玻璃/粒子边缘闪烁。建议软阈值。

### 1.2 运动矢量与相机参数
- **平方解码曲线（未确认）**：`Fsr2TranslationLayer.cpp:190-199` `sign×|m|²`，若游戏编码不是平方关系则全屏速度标定错误 → 慢速平移拖影/模糊。建议实测标定或改线性/可配置指数。
- **硬编码 camera FOV=45°、near/far=0.25/6000**（`:913-915`）：与原神实际不符会引入旋转相机深度重投影鬼影。建议从 cb0 读取或配置化。
- **jitter**：cb0 偏移 448 读取（`Dx11FsrBridge.cpp:7031`），±0.6px 守卫（`:7045`）只能挡大错；快照来自 Map/Unmap 时点（`:10033-10074`），CopyResource 路径不刷新 → 相位错位（S4）。建议 jitter 改由 cb 更新钩子同步。

### 1.3 颜色/曝光
- **Mode2/3 exposure 恒 null → 自动曝光恒开**（`:8903-9010`）：`Fsr2UseNativeExposure=1` 在正式路径**不生效**。若场景色不是线性，自动曝光与亮度相关逻辑算错。建议恢复 exposure 采集或明确关闭。
- R11G11B10F direct 路径正确（源确为 R11 才启用，`:9032-9036`）；RGBA16F 回退多一份全屏拷贝——**源已为 RGBA16F 线性时可透传，跳过 prepared 拷贝**（`Fsr2TranslationLayer.cpp:349-354,829-837`）。
- PQ 路径：ST.2084 常数正确但**无 Rec.2020→工作空间色域转换**、preExposure=1.0、10bit 无抖动 → 亮部裁剪/色偏/暗部 banding（release Mode2 下 PQ 实际基本不生效，`:9024`）。

### 1.4 低渲染精度（0.2–0.9）退化
- 0.2≈5× 上采样远超 FSR2 设计包络（官方最大 Ultra-Perf=3×，`Fsr2TranslationLayer.cpp:984`）→ 细节全失/闪烁/历史不稳。
- 建议：档位下限守卫 0.5（2× 内）；<0.5 自动关闭/降低 sharpening；保持历史稳定优先于锐化。

### 1.5 性能优化机会
- prepare pass 每帧保存/恢复 CS 状态（大量 COM AddRef/Release，`:470-534`）→ TAAU 是 PS pass，可只清不还原。
- 候选 draw 每帧 7 SRV+2 RTV+cb+viewport 查询（`Dx11FsrBridge.cpp:6663-6689`）→ 资源键跨帧稳定，可缓存、变更才重查。
- 渲染线程 INI 轮询（`:6944,7079`）每 250ms 文件系统调用 → 移后台线程。

## 2. Unity 侧优化（unity-architect）

- **直写 +0x88 绕过设置系统**：`RenderScaleMenu.cpp:85` 直写对象字段，菜单标签修补（`hooked_get_text`）本质是修补「字段改了但 UI 不知道」的分裂状态。ini 死 RVA（RenderScaleKeyPointerRva 等）表明原神存在「设置键 → 图形选项查找 → 编码 float → 下拉刷新」链路；走正规链路可统一 UI/持久化/渲染三态（L 级工程）。
- **原神图形设置不是标准 PlayerPrefs/QualitySettings**，而是 il2cpp 自定义设置系统（编码 float，未确认算法）——没有标准 API 可走，只能靠 il2cpp 符号解析。
- FufuGraphicsPlugin 流程总体合理（加载顺序 ReShade→Bridge→OptiScaler 正确、进程白名单、代理 DLL 碰撞拒绝）；问题：`WINTRUST.dll` 加载作为「加载器就绪」信号是启发式（未确认跨版本时序）；FSR4 GPU 策略在 C++（`:487-550`）与 Lua（`Install-FufuPlugin.lua:10-79`）双份实现，必然漂移 → 合并单一来源。

## 3. 反编译获取有效信息的方法论（codebase-archaeologist）

### 3.1 优先级（按性价比降序）
1. **Shader 常量/资源布局（最稳）**：结构化内省（weights 16×16、cb0≥464、jitter@448）匹配「数据/布局契约」而非代码字节，代码重排不失效 → 主识别手段。
2. **渲染精度应用函数 + 字段偏移**：+0x88 偏移与白名单是稳定语义契约；定位函数的字节签名是易损部分 → 分开管理（偏移=稳定资产，签名=易损资产）。
3. **il2cpp 对象布局**：字符串长度 `+0x10`/字符 `+0x14`（`RenderScaleMenu.cpp:322-327`）、构造假字符串（`:351-375`）——用 Il2CppDumper/Il2CppInspector 解 `GameAssembly.dll` + `global-metadata.dat` 可拿类字段偏移与具名方法 RVA，替代「猜偏移 + 快照扫描」，同时消除跨帧缓存 UAF。
4. **设置存储结构（GraphicsOption 系）**：仅在需要菜单标签修补/对抗游戏自写回时再投入。

### 3.2 工作流（把「每次版本更新手动找签名」变成「diff + 再生成」）
- 工具链：IDA Pro 或 Ghidra + **BinDiff/Diaphora** 函数级比对；il2cppDumper 解 metadata。
- 签名提取：优先函数序言 + 唯一立即数/栈帧大小；所有绝对寻址位（E8/E9 rel32、RIP-relative）通配；`PatternScanner.hpp:60-112` 的 `?` 解析与「最长非通配连续段锚点」正确。
- 唯一性验证：脚本对完整二进制要求 .text 恰好 1 处、数据段 0 处；对相邻 2-3 个历史版本跑，确认跨版本稳定或标注「版本专属」。**目前无自动化，全是人工**。
- 模块指纹：现有 `TimeDateStamp+SizeOfImage+CheckSum`（`RenderScaleMenu.cpp:123-138`）——PE CheckSum 常为 0，会退化为「时间戳+尺寸」→ 叠加 `.text` 段哈希或目标函数周边 N 字节哈希。
- 缓存失效：缓存命中后再 memcmp 复核 RVA（`:171-173`）是好模式，应推广全部条目。
- **先确认目标模块**：两插件只扫主 EXE（`GetModuleHandleW(nullptr)`，`RenderScaleMenu.cpp:709`、`AntiPlayerMosaic.cpp:490`）——需用 Process Explorer 确认渲染/il2cpp 代码是否在主 EXE（未确认）。

### 3.3 对现有实现的改进
- **唯一性失败降级**：0 匹配 → 尝试相邻版本签名集；2+ 匹配 → 调用点上下文/前后字节二次裁决，或记录全部 RVA 供离线裁决（现 60×500ms 重试只解决「代码未加载」，不解决「签名失效」）。
- **签名集版本管理**：硬编码签名（`RenderScaleMenu.cpp:46-67`、`PatternScanner.hpp:23-51`）迁到按 build 指纹索引的 sidecar（JSON），运行时选对应签名集。
- **让 ini RVA 重新有用**：RVA 不作唯一来源，作**扫描种子**——已知 RVA 处签名 memcmp 通过则免扫，不通过回退全扫描；同时修正 `ini:132`「可能崩溃」注释。
- **解耦功能**：`AntiPlayerMosaic.cpp:546-551` PlayerPerspective 失败连带禁用 HideUID——应只依赖自身签名。
- 缓存格式：schema 升 v2，键名统一，新增 `signature_set`（签名集 JSON 的 SHA256）+ `module_hash`（.text SHA-256）+ `game_version`；version 1 视为 miss 重扫，绝不硬失败。

## 4. 工具链/CI 供应链加固（developer-tooling-engineer）

### 4.1 供应链（S 级，快速止血）
1. 自更新改**固定硬编码哈希** + `known-releases.json`（CI 回填 tag→SHA256），消除「包体与 digest 同源」。
2. `api.github.com` 永远直连，代理仅下载字节；unlocker/DLSS 下载对齐硬编码哈希。
3. `third-party.lock.json`（path→sha256+version+来源）+ `Assert-VendoredManifest`，CI 打包前校验。
4. 缓存键名统一 + schema v2 + 降级策略；CI 加 checksums.txt、SHA 锁定 actions、concurrency/timeout。

### 4.2 版本适配工具链（M 级）
- `tools\GenshinSignatureTool`：输入目标模块 → 按签名集定位并验证唯一性 → 计算 RVA 生成缓存/JSON → 收敛三个签名集为单一 `signatures.json`（C++ 经 CMake `configure_file` 生成头，避免源码与工具两处硬编码漂移）。
- 版本号单一来源（version.txt → 生成 .rc），消除手工同步（现从 DLL FileVersion 反推，芙芙 .rc 需手工 `"$version.0"`）。

### 4.3 CI（M/L 级）
- 构建矩阵 {Lite, Full}×{Release}，去掉手工 `-GithubLiteOnly` 特例；复用 `Initialize-FsrBuildEnvironment.ps1` 的 NuGet 固定 SDK；sccache；`push: tags: v*` + PR 构建；`concurrency: cancel-in-progress`；权限收窄。
- L 级：产物 Authenticode 签名 + SLSA 出处 + 确定性构建；自更新多镜像 TOFU + rollback（现 `Apply-PackageUpdate.ps1` 直接覆盖无回滚点）。

## 5. 反编译合规提示

注入/Hook/内存改写可能违反《原神》用户协议（封号风险，`README.md:14` 已声明）；反编译仅限自用定位接口，不得分发游戏二进制；签名/RVA 属技术事实，工具发布遵守 GPL-3.0。本文仅描述方法论。
